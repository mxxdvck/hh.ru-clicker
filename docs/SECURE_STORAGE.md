# Защищённое хранение локальных данных

Проект хранит чувствительные данные в `data/`: настройки, cookies, browser sessions, OAuth-токены и LLM-ключи. Эти файлы не должны попадать в Git или обычные облачные папки.

## Шифрование на диске

На Windows `config.json`, `accounts.json`, `browser_sessions.json` и `oauth_tokens.json` автоматически шифруются через DPAPI текущего пользователя Windows. Дополнительный ключ для обычного локального запуска не нужен.

На Linux/macOS и сервере задайте `HH_BOT_DATA_KEY`. Тогда для этих файлов используется AES-GCM. Ключ должен быть длинным случайным секретом и храниться вне репозитория.

```env
HH_BOT_DATA_KEY=<long-random-secret>
HH_BOT_REQUIRE_ENCRYPTION=1
```

`HH_BOT_REQUIRE_ENCRYPTION=1` включает fail-closed режим: приложение не будет молча читать или создавать plaintext-файлы, если защищённый backend недоступен.

Старые plaintext JSON автоматически мигрируют в защищённый формат при чтении. Значения настроек при миграции не меняются.

## Backup

`GET /api/backup` всегда требует `X-API-Key`. Если доступно шифрование, полный backup отдаётся в зашифрованном secure-store envelope и не содержит cookies, токены или API-ключи в открытом виде.

DPAPI-backup привязан к тому же Windows-пользователю и компьютеру. Для переносимого backup между машинами используйте AES-GCM и одинаковый `HH_BOT_DATA_KEY`.

Если защищённый backend недоступен, endpoint отдаёт только redacted backup. Из него удаляются cookies, OAuth/LLM/API-ключи и credentials в proxy URL. Redacted backup предназначен для диагностики и намеренно не восстанавливается.

## Логи

Перед записью в persistent debug-log применяется дополнительная redaction: Bearer/OAuth tokens, API keys, auth cookies и логины/пароли в proxy URL заменяются на `[REDACTED]`.

Это дополнительный барьер, а не разрешение публиковать `data/debug.log*`: в логах всё ещё может быть контекст вакансий и другая персональная информация.

## Тесты и служебные скрипты

Pytest принудительно отключает автоматическую миграцию реальных локальных файлов и работает только с временным `data/`. Служебные скрипты чтения OAuth/config/accounts используют тот же `secure_store`, поэтому продолжают работать после включения шифрования.
